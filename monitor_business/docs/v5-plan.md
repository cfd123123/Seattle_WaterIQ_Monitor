# V5 阶段计划：表结构升级、数据治理与 GIS/Recharts 前端

## 1. 阶段目标

在现有 `monitor_business` 能力（检测、告警、统计、观测）基础上，新增站点维度与地图可视化能力，并逐步提升模型数据质量，形成可演示的业务驾驶舱（适合简历展示）。

---

## 2. 三阶段范围

### Phase 1：表结构升级（先打地基）

**目标**：支撑站点维度，不依赖 PostGIS 即可完成地图打点与联动。  

**范围**：

- **`monitor_station`**：站点主数据（已在当前代码落地）。
- **`water_quality_record`**：已从应用模型移除；不再作为 Phase 1 扩展对象。
- **`alert_event.station_id`**：冗余字段（已支持，便于地图聚合）。
- 若未来重新引入「检测事实表」，再单独设计迁移与索引（如 `(station_id, sample_time)`）。

**验收标准**：

- 应用可启动，DDL 自动升级成功。
- 现有 **`/api/alerts`**、**`/api/stats/*`** 等不回归（`/api/check` 非当前主路径）。
- `docs/database-schema.md` 与代码实体一致。

---

### Phase 2：数据清洗与模型重训

**目标**：提升预测一致性，减少“极端坏指标却返回 Excellent”这类可解释性问题。  

**范围**：

- 以当前业务选用的训练数据集（如 USGS 衍生特征 + 规则/人工标签）为输入。
- 清洗与导出 clean CSV（如需要）：非法负值处理、异常值裁剪（百分位/IQR）、标签口径检查（`Pollution_Level` 与关键指标一致性）。
- 用 `train_water_model.py --input` 重训模型并保留对比记录（旧模型 vs 新模型）。

**验收标准**：

- 产出 clean 数据文件、训练产物和报告。
- 关键示例样本预测结果更稳定、可解释。
- 训练流程可复现（一键脚本）。

---

### Phase 3：前端 GIS + Recharts 驾驶舱（简历重点）

**目标**：产出可演示前端 MVP（地图 + 图表 + 告警闭环）。  

**范围**：

- 地图（Leaflet）：站点点位、等级着色、点选详情。
- 图表（Recharts）：近24h 趋势、污染等级分布、告警严重度分布。
- 告警列表 + 操作：`ack` / `close`。
- 筛选条件：时间范围、城市/站点、告警状态。

**验收标准**：

- 一次 `/api/check` 后，地图/图表/列表可联动变化。
- `Poor` 告警可在前端完成处理闭环。
- 可录制 2~3 分钟演示视频用于简历展示。

---

## 3. 两天排期可行性评估

### 结论

**“三阶段全部高质量完成”在 2 天内风险很高，不建议硬压。**  
但如果以“简历可演示 MVP”为目标，**2 天可完成 Phase 1 + Phase 3 核心 + Phase 2 最小版**。

### 2 天可落地版本（建议）

- **Day 1**
  - 完成 Phase 1（表改造 + 文档同步）
  - 起前端工程，跑通地图点位与 1~2 张核心图
- **Day 2**
  - 接告警列表与 `ack/close`
  - 完成前端联调、演示脚本
  - Phase 2 仅做“数据质量报告 + 清洗脚本骨架”（重训可后置）

### 2 天后置项

- 全量数据清洗策略打磨
- 重训与模型对比报告
- 高级 GIS（空间检索、多边形圈选）与权限体系

---

## 4. 执行建议（当前）

1. 先按 Phase 1 改实体与表（不导入历史数据）。
2. 同步开工前端 MVP（地图 + Recharts + 告警闭环）。
3. 把 Phase 2 作为后续迭代，避免阻塞简历交付节奏。
